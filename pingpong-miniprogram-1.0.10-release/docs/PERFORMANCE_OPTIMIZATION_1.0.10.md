# 1.0.10 性能优化记录

## 已落地

| 路径 | 优化前 | 1.0.10 |
| --- | --- | --- |
| 发球局选球馆 | 首屏后继续拉取全部分页 | 首屏只取 1 页；搜索时再按名称/完整地址取 1 页 |
| 球馆搜索缓存 | 长驻 Tab 内无有效期、无容量上限 | 2 分钟 TTL、最多 8 个关键词的 LRU |
| 消息收件箱 | 按会话逐条读取成员、球局和消息 | 按 ID 每 20 条批量读取，只校验本批发送者的双向屏蔽记录 |
| 无未读轮询 | 1 次 inbox + 2 次无意义屏蔽查询 | 仅 1 次 inbox 查询后立即返回 |
| 失效消息指针 | 可能长期挡住更早的有效消息 | 每轮最多 10 条，在事务中复核 `userId + lastMessageId` 后清零；客户端短间隔指数退避继续推进 |
| 公开文件解析 | 最多查询 6 类媒体归属 | 只查询球馆封面、历史已通过场馆照片、已上架教练头像 3 类 |
| 并发读取 | 页面可能重复请求相同读操作 | 相同并发读合并；写入前后使旧读失效，防止迟到响应覆盖 |

仅当服务端明确返回 `recoveryPending:true` 时，消息恢复轮询才从 800ms 开始指数退避，最多回到正常的 15 秒间隔；普通预览分页不会启用快速轮询。这样可以渐进清理历史失效数据，又不会让异常状态持续放大请求。

## 验证结果

- 客户端全量测试通过。
- `api` 云函数全量测试通过。
- 结构检查与发布检查通过。
- 按当前上传排除规则估算，小程序客户端约 721KB，距离 2MB 上限约剩 1.3MB。
- 新增回归覆盖：空收件箱、超过 100 条失效指针、双向屏蔽、并发新消息防误清、缓存过期、缓存容量。

## 暂不阻塞发布的规模风险

球馆名称/地址首次搜索仍使用正则 OR。该查询无法依靠普通索引加速；当前球馆目录规模可接受，但目录增长后需要观察 CloudBase 慢查询和 P95。达到明显慢查询阈值后，优先增加规范化搜索 token/前缀字段或接入全文检索，不继续扩大客户端缓存。
