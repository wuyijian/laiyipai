# 首页展示性能优化

本页记录首页性能分支的原始对比。2026-09-28 整合版本还包含附近球馆、球友资料及原有球馆评价，完整上线依赖见 `INTEGRATION_2026-09-28.md`；不能把本分支的客户端改动范围当作整合版部署范围。

## 变化

- 首页卡片只向视图传输展示、导航所需的 21 个字段；成员列表、加入弹窗说明等详情字段保留在详情页的数据流程中。已有本地首页快照恢复时也裁剪字段。
- 提交 `setData` 前逐字段比较页面当前值，跳过未变化的标量和列表；保留列表删除、排序、名额、权限变化的完整更新。整合时保留既有的同地区球馆目录 30 秒复用；球局、教练、用户标记仍重新查询，主动刷新绕过目录复用。不缓存业务写结果或名额。
- 合并加载初始状态更新；球馆数据已就绪时，首次渲染球局就补全地址，减少稍后重复提交。
- 图片解析独立于收藏状态，主列表数据就绪后开始解析。收藏慢请求不再拖住封面；媒体回写读取当前列表，保留用户的新收藏操作和排序。
- 教练模式仅解析教练头像，不解析未展示的球馆封面；刷新时同一头像文件保持已显示图片，解析失败不清空当前可用图片。
- 图片仍遵守每批最多 20 个文件的限制。所有异步结果保留请求序号检查，避免旧筛选、旧分页或卸载后的结果覆盖新页面。

## 可复现的本地比较

在工程目录运行 `node scripts/benchmark-home.js master`。脚本读取指定基线的首页代码，与当前工作区代码使用同一组模拟 API 数据、相同 `setData` 记录器比较，不访问线上数据。测试数据为每页 50 场球局、30 家球馆、无媒体。

| 场景 | master 字节数 | 优化后字节数 | master / 优化后 setData 次数 |
| --- | ---: | ---: | ---: |
| 首屏 | 143,059 | 73,585 | 9 / 8 |
| 结果未变化的刷新 | 142,981 | 198 | 8 / 6 |
| 加载下一页 | 247,393 | 49,495 | 4 / 3 |

首屏桥接载荷下降约 49%，下一页约 80%。未变化刷新不再重复传输球局列表；分页传输球局列表从 2 次降至 1 次，不重传已有球馆列表。首屏球局先于球馆返回时，仍允许先展示球局、再补地址，不能为减少更新次数而阻塞主列表。

上述数字是本地 JSON 桥接载荷，不是网络响应体大小、真机毫秒耗时、FPS 或线上 SLA。字段比较本身有 JavaScript 开销，真机应同时采集逻辑层耗时与视图渲染耗时。未测生产服务、冷启动或真实设备。

## 验证

- `npm test`：全部通过，包括卡片字段、名额变化、导航、收藏竞态、慢请求媒体、旧请求回写、刷新、分页和批量媒体解析。
- `npm run check:structure`：通过。
- `git diff --check`：通过。
- 云端接口未修改。

真机复测应使用相同设备、网络和数据，分别覆盖冷启动、快照恢复、内容变化与未变化的刷新、连续翻页、教练切换、弱网图片失败与收藏变更；观察首屏就绪时间、滚动掉帧和桥接耗时，不用本地字节下降比例推断真机加速比例。
