# 体验、耗时与技术架构优化 · 2026-09-06

## 本轮结论

已完成本地优化与自动化验证，未部署云端、未采集真机/生产基线。这里的请求数变化由可复现测试验证，不代表线上毫秒耗时或 SLA 已达标。现场曾出现的“服务繁忙”尚无云日志证据解释根因，不能宣称已经修复。

| 场景 | 原流程 | 当前实现 |
| --- | --- | --- |
| 首页显示球局 | 等球局、球馆、标记查询全部返回 | 球局返回即更新主列表；其余独立补齐 |
| 正常首页翻下一页 | 球局 + 球馆 + 标记，至少 3 次业务请求 | 已有球馆资料时仅请求下一页球局；球馆未完成/失败则重新读取 |
| 球馆首屏 | 球馆 → 球局/教练/标记 → 图片地址 → 展示 | 球馆返回即显示名称与发起入口；其他模块独立加载 |
| 球馆教练列表 | 每次进球馆都查 | 切到教练标签才查，同一详情加载周期不重复查 |
| 两个相同并发读 | 两次云请求 | 相同参数、相同策略合并为一次；各页面收到独立对象 |
| 悬挂请求 | 等待底层返回 | 客户端总等待预算：读 8 秒、登录初始化 12 秒、其他写 25 秒 |
| 失败/未知状态 | 部分状态只能显示通用错误 | 查询有单独重试，写入超时明确结果未知，标记未知不猜测写入 |

读超时预算包含重试与退避，不是每次重试重新获得 8 秒。超时仅结束客户端等待，不表示服务器事务被取消；写操作必须查询真实状态或复用原请求编号重试。实现没有向 `wx.cloud.callFunction` 传不存在的 timeout 参数，而是在统一调用层管理等待预算。平台接口背景见 [CloudBase 官方调用说明](https://docs.cloudbase.net/recipes/add-cloud-function-wechat-miniprogram)。

## 保持模块化单体，先缩短关键路径

```text
页面：主要内容先展示，补充模块有自己的加载/失败状态
  ↓
utils/api.js：稳定业务接口
  ↓
request-policy + cloud：读策略、在途合并、等待预算、受控重试
  ↓
云函数 api：身份验证 → 限流 → 业务模块 → 数据库事务
  └─ timing：各阶段耗时、错误码、请求编号
```

本轮没有引入新服务、付费常驻实例、Redis 或跨用户结果缓存；保留服务端身份校验、限流、约球名额事务、内容审核和数据库权限边界。

- **共享查询仅限在途读**：完成后即移除，不缓存球局名额、聊天权限、认证状态、收藏或临时图片 URL。新一轮请求仍走服务端授权。
- **写入失效机制**：写入开始和结束（包括结果未知）时，清空旧读的复用关系；后续刷新不会加入写入前发出的请求。
- **显式策略白名单**：未知新接口默认按写操作处理，不因名称像 `.list` 就自动合并。指定 requestId 或 deduplicate:false 时不合并。
- **重试边界**：普通读和明确幂等的少量操作最多重试一次，使用同一 requestId 和短暂随机退避；普通业务写不自动重发。收到权限/参数/未部署错误立即返回。
- **会话重置**：清空复用关系与本地诊断；旧 bootstrap 结果不能重新填入已清空的会话。
- **生命周期与竞争处理**：页面使用请求版本丢弃旧筛选、旧分页及卸载后的响应；稍晚返回的旧标记查询不能覆盖新的标记操作或状态确认。
- **媒体安全**：视频/头像在登记结果未知时不再自动删除云文件。失败或超时不是删除可能已登记文件的依据；残留文件清理仍需核对登记记录。

## 怎样看到真实耗时

客户端仅在内存保留最近 80 条白名单样本，不自动上报，也不记录消息、手机号、OPENID、文件 ID 或 URL。

```js
// 微信开发者工具调试器，当前小程序进程。
const api = require('./utils/api')
api.diagnostics.snapshot() // samples + 按 action 分组的 p50/p95/count/failed
api.diagnostics.clear()    // 开始另一轮测量前清空
```

`page.home.ready` 与 `page.venue.ready` 是主要数据交给 setData 的耗时，不是屏幕实际绘制完成、图片加载完成或用户可点击的真机帧时间。样本量较少时 p95 仅供诊断。`venues.list` 等记录包含重试和退避的客户端等待时长。

云端搜索 `API_TIMING`：`identityMs`、`rateLimitMs`、`handlerMs`、`totalMs`、`code`、`requestId`。失败和超过 1 秒的请求全部记录，较快成功请求抽样 5%，控制日志量。`firstInvocation` 只表示该实例首次进入入口，不等于完整平台冷启动耗时。由于慢请求被全量采样，不能直接用这些日志混算无偏的全流量 p95；全流量分位数仍以平台监控或专项全量采样为准。

日志只用于定位：鉴权慢应核查用户文档读与环境；限流慢/报错应检查事务、集合和权限，不可通过关闭限流解决；业务处理慢应继续拆到具体查询、图片解析与审计等子阶段。没有数据证据时不扩大实例规格或添加新的基础设施。

## 首页下拉与开屏补充 · 2026-09-06

- 保留页面原生下拉刷新：只有回到页面顶部向下拉才刷新，普通阅读滚动不触发云请求。右上角补充独立刷新按钮。
- 主动刷新清除旧在途读取的复用关系；同一轮连续下拉合并，主列表成功或失败后立即结束动画，不等待球馆、标记或图片。后续再次下拉会发起新查询。
- 成功显示「球局已更新」/「教练列表已更新」。刷新失败保留同条件旧结果并明确提示；首次失败进入可重试错误态，不伪装成没有球局。授权失效则关闭旧列表并清理失效会话，不继续作为可用列表展示。
- 开屏显示连接/查询两个阶段，等待超过 3.5 秒显示原因提示；不自动替用户确认隐私授权。底层请求等待预算不变。
- `bootstrap` 收到 `SERVICE_UNAVAILABLE` 时最多重试一次，复用 requestId 且受原总预算约束；不增加约球/加入/付款等业务写重试，不重试权限、配置或未部署错误。
- 页面可见且发生断网→联网时，对此前的网络/超时/临时繁忙失败自动补载一次。旧请求尚未失败时恢复网络，也记住这次恢复机会；卸载解除监听，隐藏时不自动拉取。
- 新增 `tests/startup-refresh.test.js` 覆盖上述 11 项场景。本次没有修改云端函数或部署云端，客户端需重新编译/上传后才能在对应真机版本生效。
