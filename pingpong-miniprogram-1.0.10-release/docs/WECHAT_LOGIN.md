# 微信登录

## 体验

首次访问需要账号的页面时打开“微信登录”。用户主动勾选协议并点击登录后，才进行微信隐私授权与云端初始化。取消后不重复弹出，可从首页、“我的”或设置中的微信登录入口重新打开。

成功后返回原页面栈，分享参数和发布草稿不重建；不会自动发布球局、发送消息或提交加入申请。头像与昵称沿用用户主动选择/填写的能力，不强制手机号、头像或昵称授权。

已有用户通过当前微信身份关联原 `users/{OPENID}`，保留原昵称、积分、角色和业务数据；并发首次登录使用事务避免覆盖。不同 AppID 的 OPENID 是不同身份，不自动跨小程序迁移用户。

## 身份链路

`微信登录按钮 → privacy.authorize → api.bootstrap → cloud.getWXContext().OPENID → users → 脱敏 profile`

使用项目现有微信云开发身份链路，不额外调用一个未被服务端验证的 `wx.login` code，不建立第二套 token 体系。OPENID 只从微信可信上下文获取，不信任客户端传入的账号字段；客户端不存放 AppSecret、session_key 或身份 token。

官方参考：[CloudBase 微信小程序云函数身份说明](https://docs.cloudbase.net/recipes/add-cloud-function-wechat-miniprogram)、[微信头像昵称填写组件说明](https://github.com/wechat-miniprogram/mp-user-avatar)。

## 状态与权限

- 本机仅记忆当前 AppID 与协议版本，用于下次自动恢复；该偏好不是登录凭证，云端仍逐请求校验身份、封禁和注销状态。
- 会话仅在内存中保存；新启动仍通过云端取得当前资料。版本变化会重新确认。
- 拒绝授权不调用云端；登录失败不生成本地假账号；取消中的迟到响应不能重新设置登录态。
- 登录页不分享、不进入 sitemap。设置中的“重新验证”仅重新验证当前微信账号，不提供跨微信账号切换。
- 云端保存 `loginProvider:wechat`、`lastLoginAt`；新增账号保存隐私同意时间。旧记录不伪造最初同意时间。

## 部署与验收

1. 保持当前 AppID 和云环境关联，开发工具须使用有权限的微信账号，不能使用游客模式。
2. 部署新版 `cloudfunctions/api`（云端安装依赖）；无新函数、无新集合、无新依赖，不修改现有存储权限。
3. 重新编译和上传客户端，登录页已经在 `packOptions.include` 显式打包。
4. 由用户本人完成微信登录/授权，验证重开同一账号数据保留、不同账号隔离、拒绝授权和断网重试，以及分享页登录后原路返回。
5. 正式发布前填写隔离的生产云环境 ID；当前仍为占位符。

本地 `npm test`、`npm run test:cloud`、`npm run check:structure` 通过，含 10 项客户端和 5 项云端登录专项测试。自动测试不等于真机授权通过；本次未部署云函数、未代替用户授权或提交发布。
