# 场馆照片与比赛视频：上传已停用

当前版本移除比赛视频、场馆照片的上传入口、文件选择、进度和重试界面；同时移除所有个人视频展示与请求，头像上传保留。没有自动删除历史媒体、集合或索引。

## 当前交互与兼容接口

- “我的”、球友资料和球局详情均不显示或请求个人视频；`players.get` 与 `matches.get` 只返回空兼容字段，`files.resolve` 不解析 `user_videos`。
- 球馆详情保留公开场地照片预览；“管理我的已有照片”展开后才查询本人记录，保留审核状态和删除入口。
- `videos.list/remove` 仅为旧版识别和删除既有记录保留；列表不返回任何视频文件或展示元数据。`venuePhotos.list/remove`、历史媒体运营处置和注销清理继续使用原鉴权。
- `files.prepareUpload` 仅接受 `avatar`；`video/venue_photo` 返回 `FEATURE_DISABLED`。
- `videos.register`、`venuePhotos.register` 保留兼容路由，但直接返回 `FEATURE_DISABLED`，不登记文件、不消耗已有凭证、不删除历史文件。
- 启动能力标记 `videoUpload:false`、`venuePhotoUpload:false`。

## 部署顺序

本地代码不会自动改变云端。先在测试环境完成以下更新，再按发布流程部署生产环境：

1. 部署新版 `cloudfunctions/api` 与 `cloudfunctions/accountCleanup`，选择“上传并部署：云端安装依赖”。不新增依赖；后者补齐旧 `profile.videoFileIds` 的注销清理。
2. 由有权限的管理员应用 `database/security-rules/storage-owner-only.json`：客户端写入仅限本人头像路径、JPG/JPEG/PNG、5MB；拒绝 `user-videos/` 读写及 `venue-photos/` 新增写入，历史场馆照片仍仅所有者可读。个人视频也不再由公开 API 鉴权解析。
3. 重新编译、上传小程序，使上传入口和全部个人视频内容消失。
4. 验证旧版准备上传与登记调用被拒绝、旧媒体路径不能写入；确认头像上传、个人视频不公开、兼容删除和历史场馆照片管理正常。
5. 不删除 `user_videos/user_media/upload_tickets`、历史照片索引或文件目录；历史审核、媒体回调与注销清理仍需保留。

## 历史数据处理

待审核媒体不对普通用户公开文件 ID。管理员仍可处理历史审核队列；个人视频无论审核状态都不再进入用户资料或球局详情。通过审核的场馆照片与官方封面合并展示，不代表球馆认证。历史个人视频可通过兼容接口、客服或账号注销清理；场馆照片的本人删除与运营下架通过云函数移除公开引用、更新配额并清理文件。

仅上传而未登记的孤立文件不能仅按时间批量删除，须人工核对凭证与媒体引用。本次停用不执行任何数据清理。

## 验证与发布边界

`npm test`、`npm run test:cloud`、`npm run check:structure` 本地通过。专项测试覆盖个人视频入口与请求缺失、公开响应为空、通用文件解析拒绝、旧上传路由拒绝、头像凭证兼容、历史清理链路及存储规则边界。

以上为本地代码验证，未部署云函数、未变更线上权限、未进行真机云端回归。生产环境 ID 仍需配置。上线前由运营复核实际隐私说明：不再接收或展示个人视频，不再接收场馆照片，但在完成历史清理前仍会处理既有媒体及头像。
