# 球友栏目、资料分级与反馈

本分支基于 master，独立于附近球馆和首页性能分支。代码待部署。

## 入口和行为

- 首页按“找球局 / 找球友 / 找教练”并列切换，“找球友”在首页内直接展示列表及筛选；“我的”保留独立球友页入口。两处复用同一列表组件，展示所有正常公开账号；原“我的球友”仍只记录已确认同场关系。
- 筛选栏为“等级 / 行政区 / 可约 / 附近”。等级与行政区为下拉，“可约”为单项开关，关闭时不过滤状态。地区取个人资料，不代表实时位置。
- “我的状态”可设置是否可约、100 字状态说明；可约时填写北京时间日期、同日时段和公开球馆。可保存正在进行但尚未结束的时段；最远开始时间为未来 30 天。仅表达约球意愿，不自动订场或创建球局。
- 结束时刻及之后，服务端呈现为不可约；客户端列表和详情每 30 秒更新到期显示。过期安排和说明不再公开。关闭可约会清除旧时段与球馆，可保留新的普通状态说明。
- 游客可浏览公开球友。公开资料、列表和头像遵守双向屏蔽；停用及注销账号不显示。OPENID、联系方式、审核字段不出现在响应里。
- “我的”和“设置”新增微信原生问题与建议反馈入口；运营在微信公众平台客服反馈中处理，不新增自建反馈集合。

## 资料分级

资料按基本信息、积分与等级、技术特点、能力项分区录入。能力项 0 表示未评估，不等于不会；其余为学习中、定点会用、变化会用、实战熟练。旧版自由技术备注保留。

等级是产品规则，依据本人填写的开球网积分推导，尚未核验，不是官方认证：F <900；E 900–1199；D 1200–1499；C 1500–1799；B 1800–2099；A 2100–2399；S+ ≥2400。E 至 A 各按 100 分划分 3、2、1 档。积分与段位是两个并存字段：自评永不生成或修改积分。没有可换算的开球网积分时，根据能力自评估算并标记“自评参考段位”；信息不足则待定级。其他平台积分照常展示，但不直接换算。

目录原始定义位于 cloudfunctions/api/lib/player-levels.js，修改后运行 node scripts/sync-player-levels.js 同步客户端，测试检查两份一致。

## 数据与分页

profile.update 支持 playingProfile 与 availability；不传时保留旧数据，传入时整体替换对应嵌套字段。服务端验证选项、标签数量、时间、球馆公开状态并审核自由文本；球馆名称、等级和到期时间不信任客户端。

players.list 使用 publicId 升序游标，单页最多 20 条；每次最多扫描 250 条候选，按数值推导等级，兼容旧版字符串积分，无需数据迁移。命中 20 条或扫描达到上限时 hasMore=true，允许最后一次请求返回空页；稀疏筛选可能返回 items=[] 且 hasMore=true，客户端须保留“查看更多”。每批候选按确定的 block ID 检查双向屏蔽，不受用户屏蔽总数影响。

此策略保证兼容和有界请求成本；用户量增长后可迁移为服务端维护的等级数值字段及组合索引。当前不会伪造数量或因单批无命中宣称遍历完成。

## 部署与验收

1. 按 database/indexes.json 手动创建 users.status_public_id 与 users.status_district_public_id 两个索引，等待生效。
2. 部署 api 云函数后再上传客户端。新客户端检测状态保存结果，旧后端不会被误报为已保存。
3. 运营更新隐私说明，明确球友公开目录、技术自评与主动发布的时段/球馆，并按实际变更同步隐私版本。附近功能仅在主动操作时请求模糊定位。
4. 运行 npm test、npm run test:cloud、npm run check:structure。
5. 微信开发者工具及真机验收：访客浏览、组合筛选、连续翻页、拉黑后返回目录、长状态文本、弱网重试、日期/时间选择、球馆搜索、关闭可约、到期自动变化，以及原生反馈入口和后台收件。Node 测试不能验证微信原生选择器及反馈 UI。

本次未部署生产云函数、未建立生产索引、未上传小程序。

## 能力自评试行规则

正手、反手、发球、接发、步法、衔接与实战六类各至少评估两项，每类取已评项目最高的两项求平均。未评估不当作 0 分，也不强制专项技术全部掌握。各类等权，且短板限制高段位。综合平均与最弱类的门槛分别为：F 1/1，E 1.5/1，D 2.25/1.5，C 3/2.5，B 3.75/3.5。此为产品试行启发式，未经实战样本校准，不能证明实际比赛水平，不换算为开球网分数。自评只到 B 大类，不估计小档位或 A/S+；有效开球网积分优先按积分区间匹配。

## 附近球友

- 使用 wx.getFuzzyLocation（gcj02），不申请精确位置。点击“附近”才定位；拒绝后仍可按地区浏览。查询位置仅存在当前组件内存，切走页面即释放，不写本地存储、不自动共享。
- “我的状态”里明确开启“在附近展示 24 小时”才向服务端保存自己的大致位置；默认关闭。服务端进一步取 0.01 度栅格，不信任客户端过期时间。公开响应只给整数公里文字，不返回经纬度；附近不含本人，仍排除双向屏蔽和非正常账号。
- 支持 5/10/20/50 公里范围，与段位、地区、可约组合过滤。按稳定 publicId 分页，不承诺全局距离排序；稀疏页仍可继续查找。
- 到期立即停止匹配，小时 accountCleanup 定时任务每批最多清除 100 个过期位置；事务重新校验期限，避免删掉刚续期的位置。手动关闭立即写 point:null 清除位置。
- 部署还需更新 accountCleanup，并建立 users.nearby_enabled_expiry 索引；加上 app.json 中的 userFuzzyLocation 声明，申请接口权限并更新微信隐私指引。接口类型参考微信官方 api-typings 的 GetFuzzyLocationOption。
