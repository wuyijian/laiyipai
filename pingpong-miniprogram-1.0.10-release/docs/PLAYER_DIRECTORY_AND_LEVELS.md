# 球友栏目、资料分级与反馈

本分支基于 master，独立于附近球馆和首页性能分支。代码待部署。

## 入口和行为

- 首页“找球友”与“我的”入口展示所有正常公开账号；原“我的球友”仍只记录已确认同场关系。
- 支持等级大类 F/E/D/C/B/A/S+、待定级、杭州行政区、可约球/暂不约球组合筛选。地区取个人资料，不代表实时位置。
- “我的状态”可设置是否可约、100 字状态说明；可约时填写北京时间日期、同日时段和公开球馆。可保存正在进行但尚未结束的时段；最远开始时间为未来 30 天。仅表达约球意愿，不自动订场或创建球局。
- 结束时刻及之后，服务端呈现为不可约；客户端列表和详情每 30 秒更新到期显示。过期安排和说明不再公开。关闭可约会清除旧时段与球馆，可保留新的普通状态说明。
- 游客可浏览公开球友。公开资料、列表和头像遵守双向屏蔽；停用及注销账号不显示。OPENID、联系方式、审核字段不出现在响应里。
- “我的”和“设置”新增微信原生问题与建议反馈入口；运营在微信公众平台客服反馈中处理，不新增自建反馈集合。

## 资料分级

资料按基本信息、积分与等级、技术特点、能力项分区录入。能力项 0 表示未评估，不等于不会；其余为学习中、定点会用、变化会用、实战熟练。旧版自由技术备注保留。

等级是产品规则，依据本人填写的开球网积分推导，尚未核验，不是官方认证：F <900；E 900–1199；D 1200–1499；C 1500–1799；B 1800–2099；A 2100–2399；S+ ≥2400。E 至 A 各按 100 分划分 3、2、1 档。无积分及其他平台积分均显示待定级。技术标签与自评能力不改变等级。

目录原始定义位于 cloudfunctions/api/lib/player-levels.js，修改后运行 node scripts/sync-player-levels.js 同步客户端，测试检查两份一致。

## 数据与分页

profile.update 支持 playingProfile 与 availability；不传时保留旧数据，传入时整体替换对应嵌套字段。服务端验证选项、标签数量、时间、球馆公开状态并审核自由文本；球馆名称、等级和到期时间不信任客户端。

players.list 使用 publicId 升序游标，单页最多 20 条；每次最多扫描 250 条候选，按数值推导等级，兼容旧版字符串积分，无需数据迁移。命中 20 条或扫描达到上限时 hasMore=true，允许最后一次请求返回空页；稀疏筛选可能返回 items=[] 且 hasMore=true，客户端须保留“查看更多”。每批候选按确定的 block ID 检查双向屏蔽，不受用户屏蔽总数影响。

此策略保证兼容和有界请求成本；用户量增长后可迁移为服务端维护的等级数值字段及组合索引。当前不会伪造数量或因单批无命中宣称遍历完成。
