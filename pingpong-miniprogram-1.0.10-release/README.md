# 搭拍子微信小程序

“搭拍子”是一个基于杭州球馆、日期和时段的乒乓球约球小程序。产品只保留两条主路径：找球局与发起球局；已加入成员可在球局内确认时间、沟通到馆信息或取消。教练预约使用同一套时段库存与预约中心。

当前仓库是 1.0.10 发布候选工程，不含虚构球馆、教练、球局或本地业务数据回退。正式 AppID 与唯一生产云环境已写入工程；上线前仍必须由小程序管理员核对云端部署、微信隐私保护指引和真实供给。本地代码与文档更新不会自动修改云端。

## 产品原则

- 默认服务地区为杭州，用户手选行政区；首页“附近球馆”入口支持主动模糊定位，按估算距离查看 3—50 公里内已收录且有坐标的球馆。未获得定位时不显示虚构距离。详见 [附近球馆接入与验收](docs/NEARBY_VENUES.md)。
- 加入球局只需确认关键信息，不做关注、点赞、排行榜等高社交负担机制。
- 同一球局只有在成员确认加入后才自动成为球友，无需发送好友申请；首页可只看球友正在参与的球局，候补、待审批和被拒绝申请不建立关系。
- 搜索无结果时由用户主动放宽日期和球龄，再按需扩大地区，不静默改变筛选条件。
- 历史球局支持“再约一场”生成草稿；重新确认时间和订台状态，不自动发布或邀请原成员。
- 订台状态由发起人填写，加入球局不等于向球馆预订；申请、候补和已加入分别展示对应状态。
- 球龄、擅长技术均为可选资料；开球网等积分明确标注“本人填写”。
- 球局和教练费用仅作预估，到店自行支付，平台当前不代收。
- 精确地址限定为已核验公共球馆；球局聊天只对成员开放。
- 用户可录入杭州新球馆名称；通过文本安全与同名校验后立即进入公共球馆列表并可用于发布，名称型球馆会明确标注为球友补充、未经实地核验。
- 朋友圈分享仅用于首页、球局、球馆和教练公开页，只携带公开资源 ID。
- 当前版本已移除公开动态、心得发布与公开回复；球友页仅保留同场球友，旧动态链接显示下线提示，球局内沟通与消息红点保留。
- 保留 1.0.7 的头像选择与异步内容审核；审核通过前继续显示原头像或系统头像。个人比赛视频和新增场馆照片仍不开放上传，历史记录仅保留兼容删除、运营处置和账号注销清理。

## 技术架构

- 微信登录：首次明确确认，成功后恢复原页面；重登复用同一微信账号。接入与部署见 `docs/WECHAT_LOGIN.md`。
- 环境：当前只启用生产环境 `laiyipai-d2gks4fmq84ce6b44`，开发版、体验版和正式版均连接该环境；不得向真库灌入自动化测试数据。
- 客户端：原生微信小程序，页面通过 `utils/api.js` 调用统一 API，不直接访问数据库或云存储；授权运营账号可从“我的 → 运营管理”审核教练认证，并处理升级前遗留的球馆审核记录。
- 后端：微信云开发 `api` 云函数，根据登录态中的 OPENID 鉴权。
- 数据：云数据库保存用户、私有双向球友关系、公开球馆、私有球馆录入留痕、球局、成员、消息正文与未读收件箱、教练时段、预约和安全记录；历史动态与回复仅保留数据及账号注销清理，不再由业务 API 开放。数据库拒绝客户端直连，云存储仅允许用户写入自己的合规头像路径。
- 一致性：抢位、审批、取消和教练时段扣减使用事务；写操作使用 `requestId` 幂等，关键对象使用版本号防止覆盖。
- 球局编辑：`matches.create` 与 `matches.update` 保留 1.0.7 的球局标题和见面备注，并支持编辑球馆、日期、时段、人数、球龄、练球类型、加入方式、订台状态和费用；版本号与请求意图指纹防止并发覆盖或重复写入。
- 消息提醒：`messages.inbox` 返回有效会话的最新消息指针；未读数在 99 以内精确统计，更多时按 `99+` 展示。`messages.read` 仅在指针仍为最新时清零；“我的”页和第 4 个自定义 Tab 共用该状态显示红点。
- 内容安全：球局标题与备注使用同步文本检查并失败关闭；头像通过异步媒体审核回调后才生效。历史视频和场馆照片仅保留兼容处置及清理能力。
- 本地存储：只保存筛选条件、未提交草稿和协议版本，不保存业务事实。

API 契约见 `cloudfunctions/API_CONTRACT.md`，数据模型见 `database/SCHEMA.md`。

商业模式画布、试运营假设与衡量方式见 `docs/BUSINESS_REVIEW.md`。

## 本地验证

```powershell
npm test
npm run test:cloud
npm run check:structure
npm run check:release
```

`check:structure` 验证代码、权限边界和必要文件；`check:release` 还会检查正式 AppID 与生产环境配置。这些命令只做本地验证，不会部署云函数、修改数据库或发布小程序。

## 部署顺序

1. 核对 `project.config.json` 中的正式小程序 AppID。
2. 在微信云开发控制台确认唯一生产环境为 `laiyipai-d2gks4fmq84ce6b44`，并确认开发版、体验版和正式版均有意连接该环境。
3. 按 `database/README.md` 创建集合和索引，为数据库应用客户端全拒绝规则，并为云存储应用仅本人头像可写的规则。
4. 按 `cloudfunctions/DEPLOYMENT.md` 更新 `api`、`mediaCallback` 与 `accountCleanup`，启用 `event/wxa_media_check` 消息订阅并配置定时触发器。
5. 在微信公众平台配置隐私保护指引、客服和服务类目。
6. 配置管理员 OPENID；运营可从“我的 → 运营管理 → 教练认证审核”处理申请，从“历史球馆审核”处理升级前遗留申请，并通过管理员 API 维护已核验的杭州球馆、教练与时段。
7. 通过双账号并发、权限、内容审核、注销、弱网和真机回归后，再提交体验版与审核。

完整门禁见 `docs/RELEASE_CHECKLIST.md`，隐私数据清单见 `docs/PRIVACY_DATA_MAP.md`，日常审核与故障处置见 `docs/OPERATIONS_RUNBOOK.md`。杭州场馆回访清单和处于下架状态的候选导入数据分别位于 `docs/HANGZHOU_VENUE_ONBOARDING.md` 与 `database/hangzhou-venue-candidates.pending.json`。

- `utils/cloud-config.js` 已配置唯一生产环境 `laiyipai-d2gks4fmq84ce6b44`；仓库没有独立测试环境，发布前仍需确认最新版云函数、索引和安全规则已在该环境生效。
